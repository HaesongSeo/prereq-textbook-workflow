# prereq-textbook-workflow

**논문 한 편을 읽기 위해 필요한 수학만 가르치는 맞춤 교재를, Claude Code와 함께
만들기 위한 정책과 템플릿.**

읽고 싶은 논문이 있는데 선행 지식이 모자랄 때 보통 두 가지 중 하나를 한다.
표준 교재를 처음부터 읽거나, 모르는 채로 밀고 나간다. 앞의 것은 논문과 무관한
절반을 읽게 되고, 뒤의 것은 어디서 막혔는지도 모르게 된다.

이 저장소는 세 번째 길을 위한 것이다. **논문을 먼저 분석해 의존성 그래프를
만들고, 확인 문제로 독자가 이미 아는 것을 재고, 그 차이만큼만 LaTeX 교재로
쓴다.** 커리큘럼은 과목이 아니라 논문이 결정한다. 완전성과 관련성이 충돌하면
언제나 관련성을 택한다.

실제 논문 세 편에 적용하면서 다듬은 것이고, 여기 적힌 규칙 대부분은 그 과정에서
실패한 자리에 세운 것이다.

## 무엇이 들어 있나

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 프로젝트 정책. Phase 0–6의 절차, 깊이 결정 규칙, 검증 규칙, 금지 사항 |
| `PHASE1_PROBE_GUIDE.md` | 배경 진단(Phase 1)의 세부 정책. 어느 노드를 물을지, 답을 어떻게 등급으로 옮길지, 묻지 않은 노드를 그래프에서 어떻게 채울지 |
| `Source/` | 새 프로젝트를 시작할 때 통째로 복사하는 템플릿 |

`Source/` 안에는 관리 문서 세 벌(`spec.md`·`background.md`·`progress.md`)과
검사 스크립트가 들어 있다. 이 셋이 상태의 정본이다 — 정책 파일에는 진행 상태를
적지 않는다.

## 절차

| Phase | 이름 | 산출물 |
|---|---|---|
| 0 | 논문 확보 및 분석 | 의존성 그래프, 표기 용어집, 챕터 개요 (`spec.md`) |
| 1 | 배경 진단 | 노드별 지식 등급 (`background.md`) |
| 2 | 커리큘럼 설계 | 챕터별 깊이와 분량 예산 |
| 3 | 참고문헌 확보 | `refs/`, `refs.bib` |
| 4 | 교재 집필 | `tex/chapters/` |
| 5 | 논문 정독 | `tex/paper/` |
| 6 | 최종본 정리 | 머리말·부록, 전수 점검 |

각 Phase는 결과 요약과 승인 요청으로 끝난다. 승인 없이 다음 단계로 넘어가지
않는다.

## 이 방법의 골격 두 가지

**1. 깊이는 두 축이 정한다.** 노드마다 *논문에서의 사용 방식*(A–D)과 *독자의 지식
등급*(K0–K3)을 매기고, 표에서 서술 깊이(L0–L4)를 읽는다.

<!-- SSOT-COPY: depth-matrix -->

|   | K0 들어본 적 없음 | K1 진술을 알아봄 | K2 진술·적용 가능 | K3 증명 재구성 가능 |
|---|---|---|---|---|
| **A** 배경 언급만 | L1 | L1 | L0 | L0 |
| **B** 블랙박스 인용 | L2 | L2 | L1 | L0 |
| **C** 가설을 조작하며 적용 | L3 | L3 | L2 | L1 |
| **D** 증명 기법을 모방 | L4 | L4 | L3 | L1 |

L0은 제외, L1은 진술과 출처, L2는 논문에서의 역할까지, L3은 예시와 계산, L4는
완전한 증명이다. 논문이 블랙박스로 인용하는 정리를 증명까지 읽을 이유는 없고,
증명 기법을 변형해 쓰는 정리를 진술만 보고 넘어갈 수도 없다.

**2. 지식 등급은 자기보고가 아니라 확인 문제로 잰다.** "X를 아시나요?"는 묻지
않는다. 대신 논문이 실제로 요구하는 능력 하나를 재는 문제를 낸다. 질문 예산은
정해져 있으므로(턴당 5문항, 총 6턴) 전수 조사하지 않고 그래프 위에서 이진
탐색을 한다. **측정한 값과 그래프에서 추정한 값을 한 칸에 합치지 않는다** —
이 구분이 무너지면 이미 아는 내용을 다시 쓰게 되고, 그 지면은 정말 필요한
증명에서 빠져나간다. 규칙은 `PHASE1_PROBE_GUIDE.md`에 있다.

## 지어내지 않게 하는 장치

수학 교재에서 그럴듯한 거짓말은 최악의 산출물이다. 존재하지 않는 정리 번호,
있지도 않은 논문, 조용히 건너뛴 논증은 읽는 사람이 그것을 믿고 몇 주를 쓴 뒤에야
드러난다. 이 저장소의 규칙 중 상당수는 그것을 막기 위한 것이고, 대부분 실제로
당한 자리에 세워졌다.

**입력에서 막는다.** Phase 0은 **논문 전문을 확보하기 전에 시작하지 않는다.**
초록이나 리뷰, 기억으로 대신하지 않는다 — 구하지 못하면 사용자에게 PDF를 요청하고
대기한다. 참고문헌도 마찬가지다. 정리 번호를 인용하려면 기억이 아니라 검색으로
실물을 확인한 뒤 적고, **인용 키가 실제로 어느 문헌으로 렌더되는지 먼저 확정한다**
— 같은 저자의 논문이 여럿일 때 이름만 보고 동정했다가 「원문의 인용이 틀렸다」고
기록한 뒤 철회한 적이 있다.

**불확실성을 침묵시키지 않는다.** 얼버무리는 문장 대신 본문에 표시로 남긴다.

| 표시 | 뜻 |
|---|---|
| `\UNVERIFIED{}` | 출처를 특정하지 못했다. 이유를 함께 적는다 |
| `\OWNPROOF{}` | 출처에 공백이 있어 우리가 채운 논증 (출처가 결과만 진술했거나, 증명을 한 구절로 압축했거나, 다른 진술을 증명한 경우) |
| `\OWNCHECK{}` | 어느 공백도 메우지 않는, 서술 편의로 우리가 붙인 표준 보조사실이나 검산 |
| `\uncertain{}` | 확신할 수 없는 서술 |

최종본에서 이 표시를 남길지는 Phase 6에서 정하고, 남기기로 하면 책 안에 범례를
넣는다. 표시가 수십 번 나오는데 뜻을 적은 곳이 없으면 독자는 알 길이 없다.

**검사는 사람 눈에 맡기지 않는다.** 템플릿에 검사기가 딸려 있다.

| 스크립트 | 무엇을 잡는가 |
|---|---|
| `tex/check.sh` | 비ASCII 스캔 → clean-room 빌드 → `grep -a`로 로그 검사 |
| `md-check.sh` | 관리 문서의 정의되지 않은 매크로, 표를 깨뜨리는 세로줄, 열 개수, 본문 항목 번호를 `.aux`의 실제 번호와 대조, 승인 표·승인 로그·상태 블록의 불일치, 등급 열이 기호를 잃고 산문이 된 곳, 두 곳에 베낀 표가 갈라진 곳 |
| `tex/notation-check.sh` | 표기 매크로의 전개형을 손으로 써서 표기가 갈라진 곳 |
| `tex/import-check.sh` | 다른 프로젝트에서 가져온 장의 **원본이 바뀌었는가** (자동 병합하지 않고 실패시킨다) |
| `tex/<원문>-check.sh` | 본문이 텍스트로 적은 원문 정리 번호. `Thm.~8.1` 같은 것은 `\ref`를 거치지 않아 빌드가 아무것도 검사하지 않는다 |

**금지 사항.** 출처 없는 정리 진술, 참고문헌·정리 번호 날조, 원문 없이 Phase 0
진행, 승인 없는 계획 변경. 이 규칙들은 다른 모든 규칙에 우선한다.

검사기 자체가 침묵한 적도 있고, 그 경험이 다시 규칙이 되었다. `tex/` 아래
비ASCII 한 글자가 로그를 binary로 만들어 일반 `grep`이 조용히 아무것도 찾지
못했고, 실패한 빌드가 「경고 0건」으로 보고되었다. bibtex의 `note` 필드에 적어
둔 작업 메모가 최종 PDF의 참고문헌에 12쪽에 걸쳐 인쇄되었다. 나중에 추가한
파일이 검사기의 glob 밖에 있어 `\cite`가 가득한 채로 통과 표시만 받았다 —
범위를 넓히자 대조 건수가 223에서 243으로 늘었다.

**이 장치들은 모델이 틀리지 않게 만들지 못한다. 틀린 것이 조용히 남지 않게
만들 뿐이다.**

## 시작하기

```sh
git clone https://github.com/HaesongSeo/prereq-textbook-workflow.git Study
cd Study
cp -R Source "내 논문 이름"
```

`Study/`에서 Claude Code를 연다. `CLAUDE.md`는 루트에 있어 모든 프로젝트가
공유하고, 프로젝트별 설정은 각 폴더의 `spec.md` 첫머리에 적는다. 첫 프롬프트로는
`Source/progress.md`의 「새 세션 시작 방법」에 적힌 예시를 쓴다.

필요한 것: [Claude Code](https://claude.com/claude-code), TeX Live(`latexmk`,
`pdflatex`), `python3`(마크다운 검사기), 원문 PDF를 다루기 위한 `poppler`
(`pdftotext`, `pdftoppm`).

## 들어 있지 않은 것

논문 PDF, 집필된 교재, 진단 결과 같은 개별 프로젝트의 산출물은 이 저장소에
포함하지 않는다. 여기 있는 것은 방법과 빈 템플릿뿐이다.

관리 문서와 대화는 한국어로 쓰고, `tex/` 아래 교재는 기본값이 영어다. 이 설정은
프로젝트마다 바꿀 수 있다.
